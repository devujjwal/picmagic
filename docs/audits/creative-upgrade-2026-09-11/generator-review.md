# Assembled-prompt and persona review — 11 September 2026

Planning findings, not implemented changes. Evidence: `features/generator/provider.ts`, `features/generator/wizard.tsx`, `features/generator/friends-trip.ts`, `lib/prompts/persona.ts`, `types/content.ts`, all three content sources and the [record-level audit](prompt-audit.json). The local app sends prompts to users, not photos to an image model: it cannot actually inspect a visitor's age or count faces. The external-tool prompt must request suitable references when needed; UI claims must acknowledge that limitation.

## What is already correct

The local library separates `prompt_text` from `image_brief`, uses `persona_policy`/`persona_version`, and distinguishes reference-optional from reference-required generation. Person prompts give references authority and default to fictional Indian/South Asian people without a reference. Cultural styles do not determine ethnicity. Product templates generally distinguish an actual supplied product from a fictional example. Narrow edits now avoid inheriting the photoshoot's new pose, outfit and setting. Friends-trip variables, timing, reference requirement and final-title editing instructions are implemented locally. Preserve this work.

These contracts are instructions, not guarantees of another model's behaviour. A fictional preview does not prove reference-person fidelity. Keyword validation currently checks known wording and a narrow demographic pattern; it cannot establish semantic consistency.

## Regression cases

**Barefoot at blue hour:** production still contains a fixed African-couple description after an override caveat. Local text is reference-first and no longer forces that demographic; it now requests bioluminescent footprints. Preserve that fix. Both available beach images lack the glow, so neither proves alignment with the local concept. No new public activation during this audit.

**Tiny Krishna:** local copyable text explicitly permits essential waves/curls while preserving hairline and identity, and specifies the U-shaped white tilak/red centre, one feather, flute held rather than played, yellow dhoti, blue gold-edged sash and playful expression. Full-resolution asset inspection confirms these visible details. Retain it. Ask for an age-appropriate child reference on conflict; a Kids label is not permission to age-transform an adult. The old regeneration brief requires reconciliation, not a new image merely for novelty.

## Generator-wide recommendations

Keep guided photo/reel generators as customizable **utility**. Broad style/background combinations do not automatically become approved creative discovery records. The generic map/note/album reveal is a workable starter, not evidence that every output is distinctive. `improvePrompt('identity')` currently appends the human identity block even to a product or future material-art result; make refinement depend on the result's subject/medium contract. Shortening uses sentence/keyword filtering; test that it cannot remove a specific prop, action, no-reference branch, product-view restriction or artistic exception. Do not solve this with an ever-longer blacklist.

`age_group` is validated but most generation preserves original age regardless of selection. Explain that as identity preservation, or remove misleading unused controls in a later scoped change. The generic `identity` boolean should not imply identity preservation can safely be switched off accidentally. Reference-detail prose already allows explicit hairstyle changes; remove fragile string replacement approaches when revisiting it.

## Minimal content-model proposal

Reuse `prompt_text`, `image_brief`, persona policies, `content_intent`, `distinctiveness_score`, `why_ai`, editorial review/version fields, preview review status, existing collection membership and canonical ownership. Do not add parallel `user_prompt`/`preview_prompt` columns with the same meaning.

Add only `transformation_type` as a controlled editorial field (there is no dedicated equivalent today). For approved multi-person/multi-panel/art concepts, an optional structured `reference_contract` is justified: subject kinds, age compatibility, identity count or source-derived count, depiction count, allowed background extras, medium/face preservation zone, required product views. Start with an internal validated editorial object if persistent admin editing is not yet needed; migrate only when approved, with a backward-compatible default. No new remote provider, database rewrite or visitor photo upload is needed to complete this design.

Each proposal's complete assembled prompt must undergo human contradiction review plus structured checks before activation. This Phase A did not execute an image model, compare a generated identity output, or run new app tests.
