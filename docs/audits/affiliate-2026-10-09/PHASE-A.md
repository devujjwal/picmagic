# PicMagic affiliate research and integration proposal

Research date: 9 October 2026. Phase A only. Owner approval is required before implementation, program applications or commercial integration. Production release and production database changes need separate explicit authorization.

PicMagic should continue to offer free prompt discovery and copying, then help visitors choose a suitable external tool. Start with Fotor and getimg.ai as image-program application candidates, Photoroom for product photography, Adobe's general program for eligible creative subscriptions, and InVideo for selected video workflows. Keep ChatGPT and Gemini as useful ordinary recommendations. Freepik/Magnific needs its live program entry point resolved first. The 85% image / 15% video allocation is a product priority, not measured traffic.

No PicMagic affiliate approval or issued referral URL was supplied. No application was submitted, agreement accepted, affiliate link activated, application code changed, production database accessed, push made or deployment triggered. The program findings below establish public offers, not PicMagic's acceptance into them.

## Proposed minimal implementation after approval

### Provider state and data

Use exactly these application states: **Researching**, **Application required**, **Applied**, **Approved**, **Rejected**, **Unavailable**. `Applied` means the owner actually submitted; `Approved` requires acceptance evidence. A waitlist is not an application or approval. A provider can have ordinary editorial usefulness independently of cash-program state.

Monetized selection must require all of: enabled provider, Approved state, nonempty verified referral URL, confirmed eligible program/product/geography, supported capability and permitted placement. Otherwise use a verified ordinary URL with `affiliate_enabled=false`, or omit the provider if no safe suitable destination exists. Changing program, domain or affiliate URL resets verification; a rejected/unavailable/disabled program cannot keep a monetized URL active. Never fabricate IDs.

Proposed isolated table fields: `id` (stable slug; no duplicate slug column), `name`, `official_url`, nullable `affiliate_url`, `affiliate_status`, `description`, `supported_capabilities`, photo/video media scopes, feature-level access notes, `is_enabled`, bounded `priority`, `program_url`, evidence references, `last_verified_at` and `affiliate_url_verified_at`. Approval evidence/notes belong in an admin-only record or protected column access; public reads get only a curated projection. Commercial terms can remain in the maintained audit report rather than adding unnecessary commission columns. No credentials or secrets are stored. Use text names initially; logos only after asset/license permission is established.

Feature availability needs `free`, `paid`, `trial`, or `unknown` per relevant capability plus source/date; one provider-wide Boolean would mislabel paid video on a tool with free images. Evidence aging should suppress unverified price/free claims until checked; begin with a proposed 30-day review interval, manually reviewed, not a background job.

Use existing Supabase RLS and `requireAdmin()` for reads/writes. Anonymous users can read enabled public recommendation fields only; ordinary authenticated users cannot modify anything. Constraints and validation should reject Approved monetization without required verification. Adding a provider in admin is allowed as a Researching draft; new domains remain quarantined until reviewed in the trusted URL policy.

### Services and UI

Proposed modules: `AffiliateProviderRegistry` for validated cached records, `AffiliateRecommendationService` for deterministic capability filtering/ranking, and `AffiliateTrackingService` as a thin wrapper over existing GA4 `track()`. ### Admin behavior and activation controls

Affiliate Tools supports add/edit, official/referral URLs, application state, capabilities/media relevance, enable/disable, bounded display priority and verification dates. Admin changes expire the provider cache with the installed Next.js API and invalidate only affected public views. Approved URL edits require fresh validation but no code deployment when they stay inside the reviewed domain/campaign policy. Disabling stops future server renders; a page already open cannot have its external anchor retroactively withdrawn, so keep cache lifetime bounded and test invalidation. Registry errors omit recommendations rather than breaking copying or reactivating old monetized seed data.

### Analytics and measurement

| Event                       | Meaning                                                                           | Safe properties                                                                                          |
| --------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `affiliate_tool_impression` | Card becomes meaningfully visible after consent; once per provider/placement/page | provider slug, prompt_type, placement, catalog/article content_slug, destination_type, affiliate_enabled |
| `affiliate_tool_click`      | User activates Open Tool                                                          | Same bounded properties                                                                                  |
| `affiliate_outbound_click`  | Allowed outbound navigation intent was selected                                   | Same properties; destination_type distinguishes ordinary/affiliate                                       |

These event names can include ordinary recommendations with `affiliate_enabled=false`; never count them as monetized referrals. Click and outbound events describe the same interaction at different stages and must not be added together as unique clicks. An outbound event cannot prove the destination loaded or a purchase occurred.

Use existing consent-gated `track()` and strict enumerations/slug validation. No event before consent, no replay of pre-consent clicks/impressions, and stop on withdrawal. Failures must never block native link navigation. Test mouse, keyboard, modified/new-tab activation and deduplication. No prompts, images, account IDs, personal selections, raw URLs, query strings, referral tokens or external full referrers enter analytics.

Inspect GA4 Enhanced Measurement outbound-click settings before launch: Google's automatic link tracking can collect full link URLs despite safe custom events. Disable that automatic outbound collection or prove it cannot transmit affiliate parameters; an account setting change needs its own authorization. Track internal controlled slugs only. Reports show consented impressions/outbound clicks and click rate; unconsented traffic is not measured by these events. Confirmed/pending/refunded commissions come only from network reporting, with no clicks-times-rate estimate or fabricated earnings dashboard. No network reporting API integration is needed initially.
